# 部署说明

本文档说明「青词天路」的部署方式，以及线上环境的实测数据与已知限制。

---

## 〇、当前线上环境（推荐）

应用已部署到 **Cloudflare Pages**，固定域名长期可用：

| 用途 | 地址 |
|---|---|
| 应用入口 | https://qingci-cet4-xiuxian.pages.dev/ |
| 健康检查 | https://qingci-cet4-xiuxian.pages.dev/healthz |
| 状态页 | https://qingci-cet4-xiuxian.pages.dev/status |
| 元信息 | https://qingci-cet4-xiuxian.pages.dev/api/meta |

一键部署：

```bash
npm run deploy:pages
```

该命令会：构建产物 → 生成 `deploy-pages/`（含 `_routes.json`）→ 临时切换为
Pages 配置 → 上传（含 Functions bundle）→ 还原 Workers 配置 → 写入 `deploy-url.txt`。

> 注意：Pages 的 `functions/` 目录下**新增端点时，必须同步把路径加进
> `scripts/prepare-deploy.mjs` 生成的 `_routes.json` include 白名单**，
> 否则该路径会走 SPA 回退返回应用页面（HTTP 200 + HTML），
> 监控拿到的 200 是应用页而不是接口。

线上验收：

```bash
npm run probe:prod
```

实测（2026-10-03，v1.3.1，每路径 10 次采样 × 2 轮）：**80/80 达标**，
中位 235–399ms（`/healthz` 235ms、`/api/meta` 255ms、`/status` 323ms、`/` 399ms）。

## 一、部署方式总览

| 方式 | 适用场景 | 是否需要账号 | 公网可访问 | 稳定性 |
|---|---|---|---|---|
| 本地直接打开 | 个人自用、离线 | 否 | 否 | — |
| 本地 HTTP 服务 | 局域网分享、健康检查 | 否 | 否 | 高 |
| **Cloudflare Pages** | **生产环境、长期使用** | **是** | **是** | **高（当前线上形态）** |
| Cloudflare Workers | 边缘部署、接口同构 | 是 | 是 | 高（`*.workers.dev` 国内被阻断） |
| 其他静态托管 | Netlify / Vercel / GitHub Pages | 是 | 是 | 高（无动态接口，见第三节说明） |

> 早期用于临时演示的 **Cloudflare 快速隧道方案已弃用**（地址每次重启都会变化，且回源到本机），
> 本文档不再展开其配置方式。

## 二、本地 HTTP 服务

### 启动

```bash
npm install     # 零外部依赖
npm run build   # 构建产物到 dist/
npm start       # 默认 http://127.0.0.1:4173
```

### 可用接口

| 端点 | 方法 | 说明 | 返回 |
|---|---|---|---|
| `/healthz` | GET | 健康检查 | 200 + JSON（含词库条数、版本、运行时长） |
| `/status` | GET | 人类可读状态页 | 200 + HTML |
| `/api/meta` | GET | 应用元信息 | 200 + JSON（五类备考、题型、题源边界） |
| `/` | GET | 应用页面 | 200 + HTML |

### 健康检查示例

```bash
curl -s http://127.0.0.1:4173/healthz
```

实测输出：

```json
{
  "status": "ok",
  "version": "1.3.1",
  "uptimeSeconds": 12,
  "checks": {
    "lexicon": { "ok": true, "count": 4540, "expected": 4540 },
    "build": { "ok": true, "artifact": "dist/cet4-xiuxian.html" }
  },
  "runtime": { "node": "v24.18.0", "platform": "win32" },
  "timestamp": "2026-09-30T03:34:17.934Z"
}
```

### 自定义端口与监听地址

```bash
PORT=8080 npm start           # 换端口
HOST=0.0.0.0 npm start        # 监听所有网卡（局域网可访问）
```

## 三、静态托管（生产环境形态）

应用是**单文件静态资源**，不依赖服务端渲染，可直接托管。
本项目线上即为此形态（Cloudflare Pages 静态资源 + `functions/` 提供的动态接口）。

### 构建

```bash
npm run build
# 产物：dist/cet4-xiuxian.html（约 469 KB，零外部依赖）
```

### 各平台部署

| 平台 | 命令 | 备注 |
|---|---|---|
| Cloudflare Pages | `npx wrangler pages deploy dist` | 需 `wrangler login` |
| Netlify | `npx netlify deploy --dir=dist --prod` | 需 `netlify login` |
| Vercel | `npx vercel --prod dist` | 需 `vercel login` |
| GitHub Pages | 推送后 Settings → Pages 选分支 | 需仓库写权限 |

> 注意：**纯静态平台**（GitHub Pages、Netlify/Vercel 静态模式）不执行服务端代码，
> `/healthz`、`/api/meta`、`/status` 这些**动态接口不可用**；
> 此时可改用 `deploy/` 中自动生成的等价**静态检查文件** `/healthz.json` 与 `/api-meta.json`，
> 同样返回 HTTP 200 与版本、词库条数等自证字段。
> 而 **Cloudflare Pages 支持 `functions/` 目录**，本项目的三个动态接口即由
> `functions/healthz.js`、`functions/status.js`、`functions/api/meta.js` 提供
> （路由白名单见 `deploy-pages/_routes.json`）。

### 静态托管实测

| 项 | 实测值 |
|---|---|
| 入口页原始体积 | 469 KB（v1.3.1 构建产物） |
| 本机服务压缩后 | gzip 144 KB / br 128 KB（启动预热实测，2026-10-03） |
| 静态平台传输量 | 由平台按 `Accept-Encoding` 自动协商压缩，命中 CDN 后更快 |
| 依赖回源 | 无 —— 电脑关机后仍可访问 |

> 2026-09-30 在 v1.2.2 产物上模拟静态托管的补充实测：首页传输 115 KB（brotli q11），
> `/healthz.json` 响应 1.7ms。产物迭代后体积略增，结论不变：静态托管**不依赖本机开机**、**无冷启动抖动**。

## 四、服务端部署（自建 Node 服务）

若需在生产保留 `/healthz`，部署 `server.mjs` 即可。该文件仅依赖 Node 内置模块。

```bash
# 服务器上
git clone <repo> && cd qingci-cet4-xiuxian
npm run build
PORT=8080 HOST=0.0.0.0 npm start
```

### 性能优化（已内置）

| 优化 | 说明 | 效果 |
|---|---|---|
| gzip 压缩 | 对 >1KB 的文本响应自动压缩 | 469 KB → 144 KB（约 69%） |
| 压缩缓存 | 压缩结果进程内缓存并预热 | 消除重复压缩开销 |
| 启动预热 | 服务启动时预先压缩页面 | 降低首次请求延迟 |

## 五、验收命令

```bash
npm run typecheck     # TypeScript 类型门禁（tsc --noEmit）
npm run verify        # 一键：类型检查 + 构建 + 测试 + 文档核验 + 本地健康检查
npm run verify:prod   # 发布门禁：类型检查 + 测试 + 文档核验 + 线上严格采样（不达标非零退出）
npm run healthcheck   # 单独校验本地健康检查状态码与响应时间
npm run probe:prod    # 线上多轮采样（加 --strict 时任一不达标即非零退出）
```

`healthcheck.mjs` 会校验状态码为 200 且响应时间低于阈值（默认 2000ms），
不满足则以非零码退出，可直接接入 CI。

### 环境变量（Pages Functions）

在 Cloudflare Pages → Settings → Environment variables 配置；**密钥一律用 Secret 类型**，
不要写进仓库或前端代码：

| 变量 | 用途 | 当前取值 |
|---|---|---|
| `APP_VERSION` | 健康检查与元信息返回的版本号 | 部署脚本按 `package.json` 自动写入 |
| `AI_GRADING_ENABLED` | 后端 AI 批改总开关（字符串 `true` 生效） | 未设置（= 关闭） |
| `DEEPSEEK_API_KEY` | 模型密钥（占位阶段不读取） | 未设置 |
| `AI_GRADING_DAILY_LIMIT` | 每日批改调用上限（占位阶段不计数） | 未设置 |

> 前端开关 `src/config/features.ts` 与后端 `AI_GRADING_ENABLED` 需要同时打开，
> AI 批改才会真正请求 `/api/grade`；默认两者都是关闭状态。

## 六、常见问题

**Q：公网地址打不开？**
A：线上正本 `https://qingci-cet4-xiuxian.pages.dev` 托管在 Cloudflare 边缘，
与本机是否开机无关；先确认访问的是该域名（而不是本地 `127.0.0.1:4173`），
再用 `npm run probe:prod` 复采确认边缘侧状态。

**Q：健康检查偶发超过 2 秒？**
A：瓶颈通常是本机到边缘节点的带宽抖动，而不是接口本身：纯 JSON 接口
（`/healthz`、`/api/meta`）中位在 200–300ms，`/` 需要传输 469 KB 入口页才会偏慢。
多采几轮即可区分偶发抖动与真实故障。

**Q：本地服务需要常开吗？**
A：不需要。本地 `npm start` 只用于开发预览与局域网分享，关掉不影响线上访问，
也不需要任何保活进程。

**Q：静态托管后进度会丢吗？**
A：进度存在浏览器 localStorage，与部署方式无关。但清理浏览器缓存或换设备会丢失，
建议定期在「洞府」页导出 JSON 备份。
