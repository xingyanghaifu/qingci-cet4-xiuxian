# 界面「混乱度」审计基线

> 由 `npm run audit:ui --save=<名字>` 生成到 `backups/ui-baseline/<名字>.json`（本地）。
> 本文件是**入库的基线记录**，供每批次对比与审查。

## 为什么需要量化基线

用户反馈「界面很混乱」。但「混乱」是主观形容词，子代理报告「更清晰了」无法验证。
`npm run audit:ui` 把混乱度拆成可测指标，让每批次有前/后数字对照。

**指标（越低越好）**
| 指标 | 含义 | 商业级阈值 |
|---|---|---|
| 可点击 | 首屏可点元素数（选择过载） | ≤ 12 |
| 边框组 | 首屏可见边框组数（视觉噪声） | ≤ 5 |
| 字号 | 首屏不同字号档位（排版混乱） | ≤ 8 |
| 主按钮 | `.btn.solid` 数（主次不分） | ≤ 2 |
| 文案问题 | undefined / [object Object] | 0 |
| **noise** | 边框×2 + 字号（综合分） | 越低越好 |

## 审计脚本自身的三个坑（已修，记录以免重犯）

1. **模板字符串转义**：把注入页面的代码写在 `` `...` `` 里时，`\[` 会退化成 `[`，
   于是 `/\[object Object\]/` 变成**字符类** `[object Object]`（匹配任意一个字符），
   匹配到一切 —— 曾报出 16 处假「文案问题」。
   修法：用 `String(fn)` 序列化独立函数注入，并改用 `indexOf`。
2. **`offsetParent` 判可见**：本应用里它对**所有**面板都返回 `null`（即使元素真有布局），
   导致统计全为 0。改用「rect 有尺寸 + 祖先非 `display:none/visibility:hidden`」。
3. **对数组做数值求和**：`0 + []` 会变成字符串 `"[object Object]"` ——
   那个诡异的「文案问题」其实是我自己聚合逻辑的产物。
