## 4. 未完成清单（按建议顺序）

### P1-9 · `<h1>` 可访问名称 ✅ 已完成

原状：`<h1>` 的可访问名称是 **9 个模块名拼接**。屏幕阅读器不认 `:has()`，
而 9 个 `.mt` span 全部常驻 DOM，只有 CSS 在视觉上藏起 8 个 ——
读屏会把「试炼殿 背单词 单题 口语小径 心魔本 词谱 卷面与洞府 问道斗法 灵田」
连读成一句，而不是当前模块。

**做法**：静态给 9 个 span 写死 `aria-hidden`（默认 `paper` 为 `false`），
再由 `switchTab` 每次切换时重设 —— 全站 23 处切模块都过这个函数，不必逐个补。

**两个必须知道的细节**：

1. **trial 面板要分叉**。`data-tab="trial"` 对应两个标题（`words` / `single`），
   判定口径必须与 `.on` 按钮的消歧完全一致，否则会出现
   「按钮亮着单题、标题读成背单词」。`switchTab` 里已复用同一套条件
   （含模考进行中 `!paper` 的边界）。
2. **降级分支不能只靠 `aria-hidden`**。`@supports not selector(:has(*))` 原本让
   9 个标题**全部可见**、用 `·` 分隔；此时若给 8 个加 `aria-hidden`，
   就成了「屏幕上看得见却读不到」（ARIA 大忌）。故把降级 CSS 改成
   `.mt[aria-hidden="false"]{display:inline}` —— 可见性与可访问名同源，
   一个属性同时管两件事，不可能脱钩。

守卫：`tests/form-a11y.test.mjs` 6 条（静态计数 ×2、运行时 ×4），
其中「交叉验证」一条把 CSS `:has()` 规则独立解析一遍，
与 `switchTab` 的 `aria-hidden` 对答案 —— 两条路径必须收敛到同一模块。

### P2-11 · 题库分片 ✅ 已处理（审计把两个文件混为一谈）

### P2-13 · 首访主题跟随系统 ❌ **不做（审计前提不成立）**

审计原文：「`p === null` 时强制 `dataset.theme='dark'`，与
`<meta name="color-scheme" content="light dark">` **矛盾**」。

**实测这个「矛盾」不存在。** 用真浏览器在系统浅色 + 无存储（首次访问）下探测：

| 探测项 | 实测值 |
|---|---|
| `data-theme` | `dark` |
| `<html>` computed `color-scheme` | **`dark`** |
| `body` 背景 / 前景 | `rgb(13,17,23)` / `rgb(230,237,243)` |
| 原生 `<input>` computed `color-scheme` | **`dark`** |
| 原生控件背景 | `rgb(13,17,23)`（与页面同族，无花屏） |

原因：`:root[data-theme="dark"]{…color-scheme:dark}` 在**运行时覆盖了**
`<meta name="color-scheme">` 的初值。所以原生控件、滚动条都按深色渲染，
**与页面一致**。审计只比对了 meta 标签的静态文本，没看 computed 值。

**另外这也不是「没人管」的默认值**，而是 v1.6 的显式设计（暗色为品牌基线）：
- `src/services/theme.ts:37-38` 有明确注释「行为变更（v1.6）：无存储 → 暗色默认」
- `tests/theme-shortcuts.test.mjs:65` 与 `tests/a11y.test.mjs:142` **两条测试专门锁着它**
- `readPreference(null)`（存储不可用）仍返回 `auto` 跟随系统 —— 降级路径是通的

**结论**：这是**产品口味**（首访用哪个主题），不是缺陷。
「跟随系统」这个能力本身已经完整（设置里有 `auto` 档，且已通过测试）。
要改默认值 = 改产品定位，需要用户点头；与 P0-2 同类，不单方面改。

## 5. 四个必须知道的坑（都会造成静默错误）

### 坑 0：属性写在标签名之前 → 控件「不存在」，而字符串测试看不出来

**2026-10-07 发现的真实缺陷，影响 12 个控件 / 43 处调用点。**

之前 P1-8「控件可访问名」用脚本批量插入 `aria-label`，把属性插到了**标签名之前**：

```html
<aria-label="搜索单词或中文释义" input id="q" placeholder="搜单词或中文">
<!-- ↑ 第一个 token 必须是标签名，这里却是属性 -->
```

浏览器的容错解析把它当成**自定义元素** `<aria-label>`，于是真正的
`<input id="q">` **根本不存在**：

- `$('q')` 返回 null → `renderCodex()` 抛 TypeError → **词谱页整页打不开**
- 12 个控件（输入框/下拉/文本域）全部失效，涉及 43 处调用点

**为什么测试全绿还漏掉了**：P1-8 的测试扫的是**源码字符串**
（`tag.includes('aria-label="X"')`），而字符串确实包含 ——
只有**浏览器解析后**才看得出标签不存在。

**防线**：`tests/markup-structure.test.mjs`（4 条）用**宽松 HTML 解析**判断标签
是否真的存在，而不是字符串匹配。另有运行时验收
`npm run verify:minified:runtime` 断言 12 个控件在真实 DOM 里都在。

> 教训：**「字符串里有」≠「浏览器认」**。凡是关于 DOM 结构的断言，
> 必须用解析/运行时验证，不能用 `includes`。

### 坑 1：Cloudflare Pages 的 SPA 回退会伪装成「文件存在」

任何未知路径都返回 **200 + 首页 HTML**。所以 `.json()` 抛的是**解析错误**，不是 404 —— 掩盖了「文件根本不存在」这个事实。

本项目因此踩了两次：PRETCO 词表（`wordListPath === ""`，词表复用 CET-4）、以及 `/robots.txt` 返回 981 KB HTML。

**排查线上问题前先确认路径真实存在**，别被 200 骗了。

### 坑 2：CRLF ↔ LF 会悄悄顶破体积预算

模板 `src/index.template.html` 是 **CRLF**（5,772 行）。用编辑工具整文件改写时可能变成 LF，**每行少 1 字节**，5617 行就是 −12 KB，直接把单文件预算顶破。

**已在本轮踩过一次**：文件一度从 811 KB 掉到 475 KB。

**做法**：改模板优先用 Node 脚本按字节写回（`writeFileSync`），改完用脚本校验 `LF 数 === CRLF 数`。**不要**用 `WriteAllText` + `-replace` 的组合操作整份模板。

### 坑 3：体积预算的三次重定基（**当前基线 911,318 B**）

| 时点 | 基线 | 说明 |
|---|---|---|
| 原始 | 965,037 B | 阶段 F / PRETCO 之后，上限 19 KB |
| 2026-10-07 第一次 | 984,120 B | 实测开工前 HEAD 已用掉 18.64/19 KB，只剩 369 B |
| **2026-10-07 第二次（当前）** | **911,318 B** | **构建期剥离内联脚本注释后重定基** |

**为什么第二次重定基**：要做「游戏性 + 修仙机制」改造，而旧基线只剩 **4.73 KB**。
于是在 `scripts/build.mjs` 里加了内联脚本压缩（去注释 + 压空白 + 语法简化，
**不开 `minifyIdentifiers`** —— 这些脚本跨块共享全局名，改短名字会静默断开引用）。
实测省 **85.4 KB**，产物 998,731 → **911,318 B**。

**这次重定基与第一次不同**：第一次是「预算被吃完了，只好承认现实」；
这次是**真的把体积降下来了**，释放的空间可以用于新功能。

**两条守卫**（`tests/visual-v191.test.mjs`）：
1. 体积在新基线 + 19 KB 内，**且产物必须 < 950,000 B**
   （防止压缩收益被新代码悄悄吃完）
2. 产物内联脚本**不得有块注释**（防压缩被回退）；同时断言**源码注释仍在**
   （剥离只发生在产物，源文件要保持可读）

**诊断开关**：`SKIP_MINIFY=1 npm run build` 可跳过压缩，
用于「某个问题是不是压缩引入的」对照实验。

## 7. 我的错误模式（这几个坑我反复踩）

1. **`assert.deepEqual(实际值, '说明文字')`** —— 把说明写进了「期望值」槽位，断言变成永真。本轮因此出现「3 个测试假绿」。

2. **验收脚本本身出错，却当成产品 bug 去改**。本轮 5 次「失败」全部是我的脚本口径错（404.html 以 `<!DOCTYPE` 开头是对的、对话框是 11 个不是 12 个、`sitemap.xml` 本就不该出现在 HTML 里）。
   **教训：先证伪「我的判据错了」，再动产品。**

3. **假 DOM 写错却怪代码**。造 `classList` 用 `indexOf` 拼串、在 `new Function` 参数里写带点的名字、把 toggle 语义搞反 —— 都会让测试假失败。

4. **临时脚本忘删**（`_audit.mjs` 曾误入版本库，已 `git rm --cached`）。临时文件名统一 `_` 前缀，收尾用 `Remove-Item`。

5. **PowerShell 环境限制**：没有 `&&`（用 `;`）；没有 `head`/`tail`/`grep`/`gzip`；用 `npm.cmd` 不是 `npm`；用 `Select-Object -Last N`、`Select-String`。
   `node -e` 里带正则方括号或点号参数名会被 mangle —— **改写成临时 `_*.mjs` 文件**再跑。
