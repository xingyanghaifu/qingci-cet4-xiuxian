# 部署说明

本文档说明「青词天路」的部署方式，以及线上环境的实测数据与已知限制。

---

## 〇、当前线上环境（推荐）

应用已部署到 **Cloudflare Pages**，固定域名长期可用：

| 用途 | 地址 |
|---|---|
| 应用入口 | https://qingci-cet4-xiuxian.pages.dev/ |
| 健康检查 | https://qingci-cet4-xiuxian.pages.dev/healthz |
| 状态页 | https://qingci-cet4-xiuxian.pages.dev/status |
| 元信息 | https://qingci-cet4-xiuxian.pages.dev/api/meta |

一键部署：

```bash
npm run deploy:pages
```

该命令会：构建产物 → 生成 `deploy-pages/`（含 `_routes.json`）→ 临时切换为
Pages 配置 → 上传（含 Functions bundle）→ 还原 Workers 配置 → 写入 `deploy-url.txt`。

> 注意：Pages 的 `functions/` 目录下**新增端点时，必须同步把路径加进
> `scripts/prepare-deploy.mjs` 生成的 `_routes.json` include 白名单**，
> 否则该路径会走 SPA 回退返回应用页面（HTTP 200 + HTML），
> 监控拿到的 200 是应用页而不是接口。

线上验收：

```bash
npm run probe:prod
```

实测（2026-10-03，v1.3.1，每路径 10 次采样 × 2 轮）：**80/80 达标**，
中位 235–399ms（`/healthz` 235ms、`/api/meta` 255ms、`/status` 323ms、`/` 399ms）。

## 一、部署方式总览

| 方式 | 适用场景 | 是否需要账号 | 公网可访问 | 稳定性 |
|---|---|---|---|---|
| 本地直接打开 | 个人自用、离线 | 否 | 否 | — |
| 本地 HTTP 服务 | 局域网分享、健康检查 | 否 | 否 | 高 |
| **Cloudflare Pages** | **生产环境、长期使用** | **是** | **是** | **高（推荐）** |
| Cloudflare Workers | 边缘部署、接口同构 | 是 | 是 | 高（`*.workers.dev` 国内被阻断） |
| Cloudflare 隧道 | 临时演示 | 否 | 是 | 低（地址每次重启变化，已弃用） |

## 二、本地 HTTP 服务

### 启动

```bash
npm install     # 零外部依赖
npm run build   # 构建产物到 dist/
npm start       # 默认 http://127.0.0.1:4173
```

### 可用接口

| 端点 | 方法 | 说明 | 返回 |
|---|---|---|---|
| `/healthz` | GET | 健康检查 | 200 + JSON（含词库条数、版本、运行时长） |
| `/api/meta` | GET | 应用元信息 | 200 + JSON（题型、特性清单） |
| `/` | GET | 应用页面 | 200 + HTML |

### 健康检查示例

```bash
curl -s http://127.0.0.1:4173/healthz
```

实测输出：

```json

  "status": "ok",
  "version": "1.0.5",
  "uptimeSeconds": 12,
  "checks": {
    "lexicon": { "ok": true, "count": 4540, "expected": 4540 },

  },
  "runtime": { "node": "v24.18.0", "platform": "win32" },
```

### 自定义端口与监听地址

```bash

HOST=0.0.0.0 npm start        # 监听所有网卡（局域网可访问）
```

## 三、Cloudflare 快速隧道（公网访问，免账号）

适合临时演示：把本地 4173 端口映射到公网 HTTPS 地址。

```bash
# 1) 先启动本地服务
npm start

# 2) 另开一个终端，建立隧道
npx cloudflared tunnel --url http://127.0.0.1:4173
```

启动成功后会打印公网地址，形如：

```text
Your quick Tunnel has been created! Visit it at:
https://<随机名>.trycloudflare.com
```

### 实测结果

| 项 | 实测值 |
|---|---|
| 健康检查状态码 | 200 |
| 健康检查响应时间 | 稳定态 440–1392ms，中位 500ms（阈值 2000ms） |
| API 元信息 | 200，中位 457ms |
| 状态页 | 200，中位 510ms |
| 应用页面 | 200，中位 1376ms（463KB 正文回源，偶发抖动） |

> 采样命令：`npm run probe:prod`（每路径 10 次）。`/healthz`、`/api/meta`、`/status`
> 三个端点 30/30 全部达标；首页因 463KB 正文经隧道回源，偶有单次超过 2 秒，
> 生产环境建议改用静态托管（见下节）。

### 已知限制（重要）

1. **回源到本机**：隧道只是转发，本机服务停止则公网地址失效。
2. **免账号隧道无可用性保证**：Cloudflare 官方明确说明此类隧道不保证 uptime。
3. **冷启动抖动**：长时间无访问后首次请求可能达 2s 左右，属隧道建连开销，非接口性能问题。
4. **地址不固定**：每次启动会分配新的随机子域名。

**结论**：适合演示与验收，不适合作为生产环境。

## 四、静态托管（推荐用于生产）

应用是**单文件静态资源**，不依赖服务端渲染，可直接托管。

### 构建

```bash
npm run build
# 产物：dist/cet4-xiuxian.html（约 469 KB，零外部依赖）
```

### 各平台部署

| 平台 | 命令 | 备注 |
|---|---|---|
| Cloudflare Pages | `npx wrangler pages deploy dist` | 需 `wrangler login` |
| Netlify | `npx netlify deploy --dir=dist --prod` | 需 `netlify login` |
| Vercel | `npx vercel --prod dist` | 需 `vercel login` |
| GitHub Pages | 推送后 Settings → Pages 选分支 | 需仓库写权限 |

> 注意：静态托管不执行 Node，因此 `/healthz`、`/api/meta` 两个**动态接口不可用**。
> 但 `deploy/` 已生成等价的**静态健康检查** `/healthz.json` 与 `/api-meta.json`，
> 同样返回 HTTP 200 与版本、词库条数等自证字段，可直接用于验收与监控。

### 静态托管实测（本机模拟静态环境）

| 项 | 实测值 |
|---|---|
| 首页响应 | 200，传输 **115 KB**（brotli q11，原始 464 KB，减少约 76%） |
| 首页耗时 | 828ms（含本机压缩，平台侧命中 CDN 后更快） |
| `/healthz.json` | 200，耗时 **1.7ms** |
| 依赖回源 | 无 —— 电脑关机后仍可访问 |

> 静态托管的优势是消灭了隧道方案的两个短板：**不依赖本机开机**、**无冷启动抖动**。

## 五、服务端部署（保留健康检查接口）

若需在生产保留 `/healthz`，部署 `server.mjs` 即可。该文件仅依赖 Node 内置模块。

```bash
# 服务器上
git clone <repo> && cd qingci-cet4-xiuxian
npm run build
PORT=8080 HOST=0.0.0.0 npm start
```

### 性能优化（已内置）

| 优化 | 说明 | 效果 |
|---|---|---|
| gzip 压缩 | 对 >1KB 的文本响应自动压缩 | 464 KB → 142 KB（31%） |
| 压缩缓存 | 压缩结果进程内缓存并预热 | 消除重复压缩开销 |
| 启动预热 | 服务启动时预先压缩页面 | 降低首次请求延迟 |

## 六、验收命令

```bash
npm run verify      # 一键：构建 + 测试 + 文档核验 + 健康检查
npm run healthcheck # 单独校验健康检查状态码与响应时间
```

`healthcheck.mjs` 会校验状态码为 200 且响应时间低于阈值（默认 2000ms），
不满足则以非零码退出，可直接接入 CI。

## 七、常见问题

**Q：公网地址打不开？**
A：检查本机服务是否仍在运行（`npm start`）；隧道与本机服务是两个进程，任一停止都会导致不可访问。

**Q：健康检查偶发超过 2 秒？**
A：免账号隧道长时间空闲后会断开连接，首次请求需重新建连。预热一次后即恢复正常水平。

**Q：能否长期用隧道地址？**
A：不建议。请改用静态托管或带服务端的环境。

**Q：静态托管后进度会丢吗？**
A：进度存在浏览器 localStorage，与部署方式无关。但清理浏览器缓存会丢失，建议定期导出 JSON。
